## Research approach

I aim to make analytical work inspectable rather than relying on an unexplained headline score.

- **Evidence and provenance:** distinguish public-source observations, assumptions, proxies, and synthetic examples; identify source dates and data limitations.
- **Reproducibility:** document code, configurations, random seeds, and versioned inputs where available.
- **Validation:** separate software tests and sensitivity checks from claims of forecasting skill; disclose failed or incomplete review gates.
- **Uncertainty:** label model-dependent scenarios as conditional, not as observed probabilities or established facts.
- **Version control:** preserve reviewed baselines and reconcile releases and provenance before promoting revised findings.

**Project maturity varies.** Consult each repository for its methods, current release, inputs, test evidence, open issues, and limitations.

**Maritime release boundary:** the linked public maritime repository identifies v0.6.0 as its published release. A separately audited v0.6.3 research package requires provenance and version reconciliation before it can be represented as the same public release.
